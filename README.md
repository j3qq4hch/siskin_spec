# Спецификация IR — оглавление

Чистовое описание формата. Порядок изложения: **КОМПОНЕНТ → СХЕМА → ПЛАТА** —
от кирпича к изделию.

Одна сущность — одна страница. Сущность, встречающаяся в нескольких контекстах
(например `<line>` — и в символе, и в корпусе, и на плате), описана **один раз**;
из остальных глав на неё ведёт ссылка. Такие строки помечены **↗**.

> ⚠ **[reasoning.md](reasoning.md) — что мы поменяли в самом IR по ходу вычитки.**
> Там же статус каждой правки: решено / сделано в коде. Пока не сошлись —
> спека описывает будущее, а код живёт по-старому.

> **Статус: все страницы написаны.** Главы 0–2 прошли вычитку;
> **глава 3 (плата) написана 2026-08-02 и вычитку ещё не проходила.**
> Источники: [../ir_schema.md](../ir_schema.md), [../eda_ir_design.md](../eda_ir_design.md),
> [../journal/decisions.md](../journal/decisions.md), живые `.swprj` и сам код `babel/`.

## 0. Общее — сквозные правила

Действуют во всех трёх главах. Читать до всего остального.

| Страница | О чём |
|---|---|
| [Единицы и координаты](units.md) | Целые микрометры, `int32`, Y вверх, углы — целые миллиградусы |
| [Модель слоёв](layer-model.md) | Знаковое число `[!][-]N`. Механизм один, пространства у схемы и платы **разные** |
| [`<layer>`](layer.md) | Объявление слоя документа — имя, цвет, видимость |
| [Имя, атрибут, плейсхолдер](naming.md) | Формальная модель: три разных факта, которые нельзя смешивать |
| [Плейсхолдеры](placeholders.md) | Режим по первому символу: `>` подставить, `=` вычислить |
| [Рамка листа](frame.md) | Страница на холсте схемы — символ с `<shape>` на слое `98` |

### Примитивы графики

Кирпичи, из которых сложена вся геометрия — в символе, в корпусе, на схеме и на плате.

| Сущность | О чём |
|---|---|
| [`<line>`](line.md) | Отрезок |
| [`<arc>`](arc.md) | Дуга — концевая форма (две точки + прогиб) |
| [`<shape>`](shape.md) | Прямоугольник или круг, в т.ч. массив |
| [`<polygon>`](polygon.md) | Заполненный многоугольник (модель пера) |
| [`<vertex>`](vertex.md) | Вершина полигона, с прогибом |
| [`<text>`](text.md) | Текстовая аннотация |

### Атрибуты

| Сущность | О чём |
|---|---|
| [`<attr>`](attr.md) | Пользовательский атрибут — имя, значение, тип |

Отдельного тега `<description>` нет: описания — обычные атрибуты
(`description`, `sym_desc`, `fp_desc`).

## 1. Компонент

Содержимое библиотеки `.swlib`: что такое компонент и из чего он состоит.

| Сущность | О чём |
|---|---|
| [`<library>`](library.md) | Корень файла `.swlib` |
| [`<symbol>`](symbol.md) | Графика символа — **пул**, имя уникально в библиотеке |
| ↗ [`<line>`](line.md) [`<arc>`](arc.md) [`<shape>`](shape.md) [`<polygon>`](polygon.md) [`<text>`](text.md) | Графика символа |
| [`<pin>`](pin.md) | Вывод — детали здесь, модуля в главе «Схема» |
| [`<component>`](component.md) | Семейство — гейты + устройства + атрибуты |
| [`<gate>`](gate.md) | Секция — вхождение символа; единственный способ его объявить |
| ↗ [`<attr>`](attr.md) | Атрибуты компонента |
| [`<footprint>`](footprint.md) | Корпус — **пул**, имя уникально в библиотеке |
| ↗ [`<line>`](line.md) [`<arc>`](arc.md) [`<shape>`](shape.md) [`<polygon>`](polygon.md) [`<text>`](text.md) | Графика корпуса — шёлкография, сборочный, контуры |
| [`<pad>`](pad.md) | Сквозной пад (TH) |
| [`<smd>`](smd.md) | SMD-пад |
| [`<hole>`](hole.md) | Крепёжное отверстие (без меди) |
| [`<model3d>`](model3d.md) | Привязка 3D-модели к корпусу |
| [`<device>`](device.md) | **Устройство** — соответствие символа корпусу; несёт маппинг и атрибуты |
| [`<map>`](map.md) | Одна пара пин ↔ пад; гейт отдельным полем |

## 2. Схема

Изделие: `.swprj`, лист схемы, соединения, иерархия.

| Сущность | О чём |
|---|---|
| [`<project>`](project.md) | Корень файла `.swprj` |
| ↗ [`<symbol>`](symbol.md) [`<component>`](component.md) | Библиотечное содержимое, вкомпилированное в проект |
| [`<class>`](class.md) | Пул именованных наборов правил — ширина, сверло |
| [`<schematic>`](schematic.md) | Лист схемы |
| [`<compinst>`](component-instance.md) | Экземпляр компонента на листе |
| ↗ [`<attr>`](attr.md) [`<text>`](text.md) | Значения и надписи, переопределённые на инстансе |
| [`<net>`](net.md) | Цепь |
| ↗ [`<attr>`](attr.md) | Атрибуты цепи: `class`, напряжение, `max_current` |
| [`<segment>`](segment.md) | Сегмент цепи — связная группа проводов |
| ↗ [`<line>`](line.md) | Провод внутри сегмента |
| [`<junction>`](junction.md) | Точка соединения |
| [`<label>`](label.md) | Метка цепи |
| [`<pinref>`](pinref.md) | Подключение к выводу инстанса — детали **или** модуля |
| [`<note>`](note.md) | Блок markdown — «textbox»; ширина задана, высота от контента |
| ↗ [`<line>`](line.md) [`<text>`](text.md) | Оформление листа |

### Иерархия

| Сущность | О чём |
|---|---|
| [`<module>`](module.md) | Определение модуля — переиспользуемый кусок схемы |
| ↗ [`<pin>`](pin.md) | Пин модуля — то, что раньше звалось портом |
| [`<modinst>`](module-instance.md) | Экземпляр модуля — канал |
| ↗ [`<pinref>`](pinref.md) | Подключение к пину модуля — тот же тег, что у детали |

## Чего ещё нет

**Главы «Импорт и экспорт».** Правила, касающиеся не устройства формата, а
поведения конвертеров, пока записывать некуда. Что уже решено и ждёт этой главы:

| Правило | Откуда |
|---|---|
| Из проекта можно выгрузить библиотеку с использованными в нём устройствами | было в [naming.md](naming.md), вынесено как чужеродное |
| Осознанные потери при импорте должны попадать в лог | [reasoning.md](reasoning.md) |
| Как каждая сущность ложится на Eagle, KiCad и Altium | черновые заготовки — [../mapping_notes.md](../mapping_notes.md) |
| Метки в исходнике должны сидеть точно на концах проводов — иначе KiCad, привязывающий геометрически, теряет связь | правило гигиены источника, не формата |
