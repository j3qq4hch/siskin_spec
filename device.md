# `<device>`

*устройство — соответствие символа корпусу; размещаемая и покупаемая единица*

| | |
|---|---|
| **Встречается в** | компонент |
| **Родители** | [`<component>`](component.md) |
| **Дети** | [`<map>`](map.md), [`<attr>`](attr.md) |

## Атрибуты

| Атрибут | Тип / единицы | Смысл |
|---|---|---|
| `name` | Строка, **может быть пустой** | Суффикс к имени семейства. Уникален в пределах компонента |
| `footprint` | Строка | Имя [корпуса](footprint.md) из пула библиотеки |

## Описание

Устройство — это **соответствие символа корпусу**, и только оно знает про такое
сочетание. [Символ](symbol.md) о корпусе не знает, [корпус](footprint.md) о
символе — тоже; оба лежат в пулах как самостоятельная геометрия.

Поэтому именно здесь живут два факта, которых больше негде взять:
[`<map>`](map.md) — какой пин на какой пад, и [`<attr>`](attr.md) — партномер,
поставщик, допуск.

```xml
<component name="RESISTOR" prefix="R">
  <gate name="" symbol="R" x="0" y="0" />
  <device name="-0603" footprint="R0603">
    <map gate="" pin="1" pad="1" />
    <map gate="" pin="2" pad="2" />
    <attr name="PACK" value="0603" />
  </device>
  <device name="-0805" footprint="R0805"> … </device>
</component>
```

[`<component>`](component.md) — **семейство**: общий символ (или набор символов
через [`<gate>`](gate.md)) плюс N устройств. Один резистор с семью корпусами
остаётся одним резистором.

## Почему `<map>` живёт здесь

Потому что маппинг — факт **пары**, а не любой из её половин.

- У разных корпусов разная нумерация падов: B/C/E в SOT-23 и TO-220 распаяны
  по-разному. Один маппинг на весь компонент был бы неверен.
- Один и тот же корпус может входить в семейство **дважды с разным маппингом** —
  семейство резисторов включает `R0603` двумя устройствами, `-0603` и `-0603-1`,
  с зеркальной распиновкой. Значит маппинг не свойство корпуса.

## Имя — суффикс к имени семейства

Оба имени задаёт пользователь. Отображаемое имя устройства — **склейка без
разделителя**:

```
имя_компонента + имя_устройства
```

| Компонент | Устройство | Пользователь видит |
|---|---|---|
| `RESISTOR` | `-0603` | `RESISTOR-0603` |
| `CON-2P` | `-XH` | `CON-2P-XH` |
| `XC6206P332` | *(пусто)* | `XC6206P332` |

**Пустое имя легально** и типично, когда в семействе одно устройство: приписывать
нечего, и отображается просто имя компонента.

Разделитель в имя не встроен: дефис в `-0603` — часть имени, которую написал
пользователь. Захочет `RESISTOR_0603` — назовёт устройство `_0603`.

## Идентичность

Уникальность — **в пределах компонента**, не библиотеки. Полный адрес устройства
это `компонент + имя`.

Имя корпуса на роль идентичности не годится: одно посадочное место может нести
несколько устройств, если у них **разная физика** — см.
[`<footprint>`](footprint.md).

## Правила

- **`name` уникально внутри компонента.** Имя корпуса — нет, оно может
  повторяться среди устройств одного семейства.
- **Пустое имя — значение, а не отсутствие.** Пишется `name=""` явно; двух
  устройств с пустым именем в одном компоненте быть не может.
- **Устройство создаётся в библиотеке, а не при размещении.** Оно несёт маппинг и
  атрибуты — это авторская работа; при размещении устройство *выбирают*.
- Устройство наследует поля [компонента](component.md) и может **добавить свои** —
  они остаются только у него. Удалить унаследованное нельзя, можно очистить
  значение; см. [naming.md](naming.md).
- Устройство без [`<map>`](map.md) легально, если у символа **нет выводов**:
  механика — крепёж, стойки, логотип из библиотеки. Появился хоть один вывод —
  нужен и маппинг, см. [`<component>`](component.md).
- **Каждый вывод разварен в каждом устройстве.** Пропуск — [ошибка, а не
  способ сказать «в этом корпусе его нет»](map.md); корпуса с разной распиновкой
  описываются разными компонентами.
- **У вывода падов может быть несколько** — термопад, лапка, силовая гребёнка;
  обратное запрещено, см. [`<map>`](map.md).
- **`footprint` разрешается в библиотеке своего компонента.** [Адрес корпуса —
  пара `(library, name)`](footprint.md), и вторая половина берётся из
  [`<component library>`](component.md), а не пишется здесь.
- **Компонент без устройств легален** — символы питания и рамки листа живут
  только на схеме и на плату не попадают.
- **Устройство — физический вариант.** Закупочные альтернативы одной и той же
  физики различаются [закупочными атрибутами](attr.md) `BOM.*`, а не отдельными
  устройствами.
