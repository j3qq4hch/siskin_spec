# `<pinref>`

*подключение цепи к выводу инстанса*

> 🟡 **Изменение формата, решено 2026-07-31, в коде не сделано.**
> Сущности `<portref>` больше нет — раз порт это [пин](pin.md), то и ссылка на
> него та же самая. См. [reasoning.md](reasoning.md) «Порты упразднены».

| | |
|---|---|
| **Встречается в** | сегмент цепи |
| **Родители** | [`<segment>`](segment.md) |
| **Дети** | — |
| **Ссылается на** | [`<compinst>`](component-instance.md) или [`<modinst>`](module-instance.md) + его [`<pin>`](pin.md) |

## Атрибуты

| Атрибут | Тип / единицы | Смысл |
|---|---|---|
| `inst` | Строка | `name` [экземпляра](component-instance.md) — детали **или** модуля. _Ранее `part`_ |
| `pin` | Строка | Имя [вывода](pin.md) этого экземпляра |

## Описание

Цепь не хранит список выводов напрямую. Она состоит из [сегментов](segment.md) —
связных кусков проводов; внутри сегмента лежит его геометрия и вот эти ссылки на
то, к чему он подключён.

```xml
<net name="GND">
  <segment>
    <pinref inst="U1"    pin="OUT-" />   <!-- вывод детали -->
    <pinref inst="DCDC1" pin="GND"  />   <!-- вывод модуля — тот же тег -->
    <line x1="104140" y1="233680" x2="106680" y2="233680" width="152" />
    <junction x="106680" y="233680" />
  </segment>
</net>
```

## Правила

- **Один тег на оба случая.** С точки зрения цепи безразлично, что внутри
  инстанса — деталь или кусок схемы. Разделение здесь было ложным: код всё равно
  сшивал `pinref` и `portref` обратно в один список при каждом использовании.
- Имена инстансов — компонентов и модулей — в одном пространстве имён, поэтому
  `inst` разрешается однозначно.
