# Из/в Eagle

*частности переноса; общие обязательства — в [контракте](conversion.md)*

## Eagle глазами IR

**Самый близкий из трёх.** Модель IR отсчитывалась от Eagle, поэтому перекодировок
здесь почти нет: деление на символ, корпус и связывающее их устройство — родное
для обоих, [ассоциация символ↔корпус живёт в библиотеке](device.md), а не
собирается со схемы.

Отсюда и объём страницы: она короче двух остальных потому, что преобразовывать
почти нечего.

Отличие ровно одно, зато структурное:

| | Уровни |
|---|---|
| Eagle | `deviceset` → `device` → `technology` — **три** |
| IR | [`<component>`](component.md) → [`<device>`](device.md) — **два** |

## Библиотеки: technology разворачивается в компоненты

Третьего уровня в IR нет: `technology` в Eagle — это не другая физика, а **другой
набор атрибутов** (`-1%`, `-5%`), то есть ровно то, ради чего существует
компонент.

Поэтому один `<deviceset>` даёт **список** компонентов — по одному на реальную
технологию, с именем вида `RESISTOR-1%`: суффикс приписывается к имени
deviceset'а, как его пишет и сам Eagle. Единственная безымянная технология
суффикса не получает.

Остальное переносится один в один:

| Eagle | IR |
|---|---|
| `<symbol>` | [`<symbol>`](symbol.md) |
| `<package>` | [`<footprint>`](footprint.md) |
| `<gate>` | [`<gate>`](gate.md) |
| `<device package=>` | [`<device>`](device.md) |
| `<connects><connect>` | [`<map>`](map.md) |
| `<class>` + `class=` на цепи | [`<class>`](class.md) |

**Корпус, не используемый ни одним устройством, отбрасывается.** У проекта нет
места для корпуса, лежащего сам по себе: `.swprj` содержит компоненты, а не
отдельные посадочные места. Отброшенные корпуса перечисляются в логе поимённо.

**Столкновения имён разрешаются переименованием, а не слиянием:** две библиотеки
с одним ником, два разошедшихся по содержимому символа или компонента под одним
именем — второй получает новое имя, и оно попадает в лог. Молчаливое объединение
разного содержимого [запрещено контрактом](conversion.md).

## Что теряется

### При импорте

| Что | Чем становится |
|---|---|
| **Шины** (`<bus>`) | содержимое не моделируется; сигналы-члены остаются обычными [цепями](net.md) — утрачивается только групповая запись |
| **Автоматические размеры** падов и переходов | **запекаются** числами из `designrules` restring: [авторазмеров в IR нет](via.md) |
| **Пары зазоров** `designrules` | сводятся в один `clearance` по **максимуму** различающихся |
| **Варианты сборки** (`<variantdef>`) | не переносятся ни в одну сторону: их не читает парсер и не пишет экспортёр |
| **Атрибуты, заданные только на плате** | отбрасываются: атрибут — факт схемы |
| **Airwires** | не хранятся: [ратснест производен](signal.md) |
| **Медь на немедных слоях** внутри сигнала | отбрасывается: [сигнал содержит только медь](signal.md) |
| **Пустые сигналы** | отбрасываются: ни `contactref`, ни меди — соединять нечего |
| **Часть декоративной графики** | отдельные типы `<plain>` пока не импортируются |

**3D-модели — отдельный случай.** Eagle не хранит привязку модели к корпусу
вовсе, поэтому найденный рядом файл размещается с **единичным преобразованием**:
без поворота и смещения. Это заведомая аппроксимация; она записывается в лог
поимённо и требует проверки в 3D.

### При экспорте

| Что | Чем становится |
|---|---|
| [`<note>`](note.md) | обычным текстом; **изображения в нём утрачиваются** — растра у Eagle нет |
| Толщина штриха у [текста](text.md) | отбрасывается: Eagle её не выражает |
| Описание, переопределённое на экземпляре | отбрасывается: у Eagle описание живёт в библиотеке, и родной слот имеет приоритет |
| Объект на слое, не имеющем соответствия в Eagle | отбрасывается с указанием номера |
| Вывод детали без корпуса | становится `sup`: Eagle допускает беспадовыми только питающие выводы |

**Обозначения компонентов приводятся к ЗАГЛАВНЫМ.** Eagle не допускает строчных
букв в именах падов, выводов и сигналов. Капитализация выполняется **только
экспортёром**; IR и парсеры остаются нейтральными, чтобы особенность одного
инструмента не распространялась на формат.

## Что отвергается

Отказ вместо аппроксимации — по [четвёртому обязательству
контракта](conversion.md).

| Отказ | Основание | Исправление |
|---|---|---|
| **Глухие и погребённые переходы** — в `layerSetup` либо у конкретного `<via extent=>` | [IR выражает только сквозные](via.md) | развести сквозными либо не переносить |
| **Лист без рамки** или с двумя рамками | [рамка задаёт страницу](frame.md); без неё принадлежность объекта листу не определена | оставить ровно одну рамку на лист |
| **Модуль внутри модуля** | [глубина ровно 1](module.md) | расплющить вложенный уровень |
| **Точка в имени гейта** | кодировка `ГЕЙТ.вывод` перестаёт читаться однозначно | переименовать гейт |
| **Деталь на плате с падами, но без схемного экземпляра** | [связность задаёт только схема](layout.md); идентичность по обозначению нарушена | завести деталь на схеме |
| **Сегмент цепи, касающийся деталей на разных листах** | сегмент обязан оставаться на одной печатной странице | разделить сегмент меткой |

При экспорте той же дверью закрыты компонент и декоративный объект, не попавшие
**ровно в одну** рамку: Eagle требует определённой страницы для каждого
нарисованного объекта.

## На что обратить внимание после конвертации

По убыванию цены ошибки:

1. **Лог переименований.** Библиотека, символ или компонент могли получить новое
   имя из-за столкновения. Это единственное изменение, затрагивающее **адреса**,
   и единственное, которое иначе не обнаруживается.
2. **3D-сцена.** Модели размещены единичным преобразованием; повёрнутые и
   смещённые корпуса требуют ручной правки.
3. **Диаметры падов и переходов.** Там, где Eagle вычислял их автоматически,
   теперь записаны конкретные числа — проверить значения.
4. **Зазоры.** Различавшиеся пары сведены к одному максимуму: правила стали
   строже исходных. Перепроверить DRC.
5. **Технологии.** `R-1%` и `R-5%` — теперь **разные компоненты**, а не одна
   деталь с переключателем. Для BOM результат тот же, для навигации по
   библиотеке — иной.
6. **Шины.** Групповая запись утрачена; убедиться, что все цепи присутствуют
   поимённо.

> **Известное ограничение ERC.** В отдельных конфигурациях Eagle сообщает об
> ошибке consistency на питающих выводах. Это его собственное поведение, а не
> дефект переноса; устраняется в Eagle и к формату отношения не имеет.
