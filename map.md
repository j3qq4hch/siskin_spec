# `<map>`

*соответствие вывода символа падам корпуса*

| | |
|---|---|
| **Встречается в** | устройство |
| **Родители** | [`<device>`](device.md) |
| **Дети** | — |

## Атрибуты

| Атрибут | Тип / единицы | Смысл |
|---|---|---|
| `gate` | Строка, может быть пустой | Имя [секции](gate.md) — какого вхождения символа |
| `pin` | Строка | Имя [пина](pin.md) внутри символа этой секции |
| `pad` | Строка | Имя [пада](pad.md) или [SMD](smd.md) в [корпусе](footprint.md). **Несколько — через пробел** |

## Описание

Связывает вывод символа с падом корпуса. Живёт в [`<device>`](device.md), потому
что это факт **пары** «символ + корпус», а не свойство любой из половин — см.
[почему там](device.md).

```xml
<device name="-0603" footprint="R0603">
  <map gate="" pin="1" pad="1" />
  <map gate="" pin="2" pad="2" />
</device>
```

## Один пин — несколько падов

Вывод приходит на несколько площадок сразу — это норма, а не экзотика.

| Случай | Что происходит физически |
|---|---|
| **термопад** QFN, DFN | `GND` разварен и на боковые пады, и на площадку под брюхом |
| **лапка** TO-220, DPAK | вывод и теплоотводный фланец — одна ножка кристалла |
| **силовая и земляная гребёнка** | ток не лезет в один пад, его разводят на несколько |
| **кастеллированный модуль** | одна цепь выведена парой площадок |

Записывается это **списком в `pad`**:

```xml
<device name="-VQFN" footprint="VQFN-24">
  <map gate="" pin="GND" pad="12 EP" />   <!-- боковой пад и площадка под брюхом -->
  <map gate="" pin="VIN" pad="1" />
</device>
```

### Почему список, а не запись на пад

Потому что факт **один**: «вывод `GND` разварен вот на эти площадки». Разложить
его по записям значило бы рассыпать одно утверждение по строкам, между которыми
формат связи не видит, — а связь тут и есть главное: пин один.

Разбор при этом однозначен **по построению**: пробел [в имя пада не
входит](pad.md), значит split не встретит его внутри токена. Этим случай и
отличается от отвергнутого ниже `pin="A.1"`, где разделитель был законной частью
имени — и потому двусмысленным.

## Вывод без пада — ошибка, а не состояние

Пад без маппинга законен, вывод без маппинга — нет, и асимметрия эта не
формальная.

**Вывод, которому не назначен пад, — ложь на чертеже.** К нему можно подвести
провод, и провод будет выглядеть подключённым; а на плате [у цепи не окажется
конца](signal.md), потому что [дорога со схемы к паду идёт только
через `<map>`](signal.md). Расхождение схемы с платой, возникшее из ничего.

Это [та же доктрина, что у неразваренного вывода](pin.md): «не разварен в корпусе
— вывод **не создаётся**». Просто там она сказана про один корпус, а здесь
доводится до семейства с несколькими.

### Разная распиновка — это разные компоненты

Обычный случай: один кристалл, два корпуса, и в меньшем часть выводов не
разварена. Соблазн — оставить общий символ и не писать лишние `<map>` у второго
устройства. Так нельзя: символ у них тогда **обещает то, чего нет**.

| Что нужно | Как делается |
|---|---|
| выводы разварены везде одинаково | один компонент, N устройств |
| в каком-то корпусе вывода нет | **отдельный символ и отдельный компонент** |

Цена — второе описание в библиотеке. Но она честная: два корпуса с разной
распиновкой это и есть две разные вещи для схемотехника, и рисуются они
по-разному. [Общий корпус у разных семейств — норма](footprint.md), обратное тоже
верно.

> Проверить это внутри библиотеки можно целиком: и выводы, и маппинг лежат
> рядом. Отдельного места для проверки не нужно.

## Направление асимметрично

**У пина падов много, у пада пин один.** Это не соглашение, а физика:

| | Можно | Что это значит |
|---|---|---|
| один пин → N падов | **да** | одна ножка кристалла разварена на несколько площадок |
| один пад → N пинов | **нет** | два разных вывода в одной площадке — короткое замыкание |

Отсюда правило уникальности: имя пада встречается внутри устройства **не более
одного раза** — ни дважды в одном списке, ни в списках разных выводов.

## Гейт — отдельное поле, а не часть имени пина

Адрес вывода состоит из **двух фактов**: какая секция и какой пин. У
четырёхсекционного разъёма символ один, пины `1`…`10`, значит пин `1`
существует четырежды:

```xml
<map gate="A" pin="1" pad="A1" />
<map gate="B" pin="1" pad="B1" />
```

Раньше это писалось как `pin="A.1"`. Плохо по двум причинам:

- **атрибут `pin` содержал не пин** — у символа нет вывода с именем `A.1`,
  у него есть `1`;
- **резолюция требовала разбора строки**, а точка в имени пина законна — мы сами
  приняли её как конвенцию группировки сигналов. Пин `CLK.P` в двухсекционном
  компоненте ломал бы split.

На список падов этот довод **не переносится**: там разделителем служит пробел,
которого в именах падов не бывает.

## Правила

- `gate` обязан существовать среди [гейтов](gate.md) компонента.
- `pin` обязан существовать в символе **этого** гейта.
- `pad` обязан существовать в [корпусе](footprint.md), на который ссылается
  устройство.
- **Имя пада не повторяется** внутри устройства — ни в одном списке дважды, ни в
  списках разных выводов.
- Порядок имён в списке ничего не значит.
- **Имена сопоставляются без учёта регистра** — [как везде, кроме
  обозначений](naming.md): `pin="vref"` находит `<pin name="Vref">`. Показывается
  при этом написание объявления, то есть символа.
- **Маппинг явный.** Совпадение имён пина и пада ничего не значит и ничего не
  подразумевает — пары нет, пока она не записана.
- **Пад без маппинга законен** — механический, крепёжный, реперный. Он [ни к
  какой цепи не принадлежит](contactref.md), и это нормальное состояние.
- **Вывод без маппинга — ошибка**, и [обратное направление тут не
  симметрично](#вывод-без-пада--ошибка-а-не-состояние). Каждый [пин](pin.md)
  каждого [гейта](gate.md) обязан быть разварен в **каждом**
  [устройстве](device.md) компонента.
