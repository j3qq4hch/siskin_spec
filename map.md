# `<map>`

*одна пара пин ↔ пад*

> 🟡 **Изменение формата, решено 2026-07-31, в коде не сделано.**
> Гейт вынесен в отдельный атрибут. Раньше писалось `pin="A.1"` — гейт и пин
> склеенные точкой. См. [CHANGES.md](CHANGES.md).

| | |
|---|---|
| **Встречается в** | устройство |
| **Родители** | [`<device>`](device.md) |
| **Дети** | — |

## Атрибуты

| Атрибут | Тип / единицы | Смысл |
|---|---|---|
| `gate` | Строка, может быть пустой | Имя [секции](gate.md) — какого вхождения символа |
| `pin` | Строка | Имя [пина](pin.md) внутри символа этой секции |
| `pad` | Строка | Имя [пада](pad.md) или [SMD](smd.md) в [корпусе](footprint.md) |

## Описание

Связывает вывод символа с падом корпуса. Живёт в [`<device>`](device.md), потому
что это факт **пары** «символ + корпус», а не свойство любой из половин — см.
[почему там](device.md).

```xml
<device name="-0603" footprint="R0603">
  <map gate="" pin="1" pad="1" />
  <map gate="" pin="2" pad="2" />
</device>
```

## Гейт — отдельное поле, а не часть имени пина

Адрес вывода состоит из **двух фактов**: какая секция и какой пин. У
четырёхсекционного разъёма символ один, пины `1`…`10`, значит пин `1`
существует четырежды:

```xml
<map gate="A" pin="1" pad="A1" />
<map gate="B" pin="1" pad="B1" />
```

Раньше это писалось как `pin="A.1"`. Плохо по двум причинам:

- **атрибут `pin` содержал не пин** — у символа нет вывода с именем `A.1`,
  у него есть `1`;
- **резолюция требовала разбора строки**, а точка в имени пина законна — мы сами
  приняли её как конвенцию группировки сигналов. Пин `CLK.P` в двухсекционном
  компоненте ломал бы split.

## Правила

- `gate` обязан существовать среди [гейтов](gate.md) компонента.
- `pin` обязан существовать в символе **этого** гейта.
- `pad` обязан существовать в [корпусе](footprint.md), на который ссылается
  устройство.
- **Маппинг явный.** Совпадение имён пина и пада ничего не значит и ничего не
  подразумевает — пары нет, пока она не записана.
