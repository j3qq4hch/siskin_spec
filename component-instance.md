# `<compinst>`

*размещение одной секции детали на холсте схемы*

> 🟡 **Изменение формата, решено 2026-08-10, в коде не сделано.**
> Part-уровень вынесен в [`<part>`](part.md): `name`, `library`, `component`,
> `device` и [`<attr>`](attr.md) переехали туда, здесь осталась ссылка `part`.
> См. [reasoning.md](reasoning.md).
>
> Ранее (2026-07-31) тег назывался `<instance>` и обслуживал два понятия сразу;
> экземпляр модуля отличался наличием атрибута `module`.

| | |
|---|---|
| **Встречается в** | схема, модуль |
| **Родители** | [`<schematic>`](schematic.md) |
| **Дети** | [`<text>`](text.md) |

## Атрибуты

| Атрибут | Тип / единицы | Смысл |
|---|---|---|
| `part` | Строка | Чья секция размещена — `name` [детали](part.md) |
| `gate` | Строка, может быть пустой | Какая [секция](gate.md) размещена. Пустое имя — обычный случай |
| `x` `y` | Целое, [µm](units.md) | Точка вставки символа |
| `rot` | Целое, [мград](units.md) | Поворот. [Кратен `90000`](units.md) |
| `mirror` | `0` / `1` | Зеркальное отражение |

Всё, что у детали одно на все секции — обозначение, устройство, партномер, —
живёт в [`<part>`](part.md). Здесь только то, что **своё у каждой секции**.

## Секция размещается отдельно

Размещается **одна секция**, а не весь компонент. Четырёхсекционный разъём даёт
четыре `<compinst>` на одну [деталь](part.md):

```xml
<part name="CON1" library="Connectors" component="1734037-4" device="-XH" />
<compinst part="CON1" gate="A" x="0"     y="0" />
<compinst part="CON1" gate="B" x="33020" y="0" />
```

Они могут стоять на разных страницах, но на плате это **один**
[`<element>`](element.md) — физическая деталь одна.

Односекционная деталь ничем не отличается: у неё ровно один `<compinst>` с
пустым `gate`.

## Что переопределяет секция

[`<text>`](text.md) — раскладку [плейсхолдеров](placeholders.md), см.
[naming.md](naming.md).

Список `<text>`, если он есть, **исчерпывающий**: что не перечислено — удалено,
а не унаследовано. Ни одной записи — секция читает раскладку прямо из
[символа](symbol.md).

Наборы записей у секций **независимы**: `>NAME`, подвинутый у секции `A`, у
секции `B` стоит где стоял.

## Чем отличается от экземпляра модуля

Понятия разные настолько, что общего тега им мало:

| | `<compinst>` | [`<modinst>`](module-instance.md) |
|---|---|---|
| что внутри | секция детали | кусок схемы |
| адрес | [`part`](part.md) + `gate` | `module` |
| [атрибуты](attr.md) | нет — они у [детали](part.md) | **есть** — параметры канала |
| `offset` нумерации | нет | **есть** |
| выбор [варианта](variant.md) сборки | нет — вариант выбирают у всей схемы | **есть** — свой у каждого канала |
| попадает на плату | как [`<element>`](element.md) | разворачивается в детали внутри |
| автопереименование | по `prefix` компонента | по своим правилам канала |

Канал не делится на секции ([их у модуля нет](module.md)), поэтому `<modinst>`
на две записи не разрезан: логический канал и его размещение — одно и то же.

## Правила

- **`part` обязан существовать** на этой схеме.
- **Пара (`part`, `gate`) уникальна** — секция размещается ровно один раз.
- `gate` обязан существовать среди [гейтов](gate.md) компонента, на который
  ссылается деталь; пустое имя — значение, а не отсутствие.
- Своего `name` у секции **нет**: адресуют деталь, а не её размещение. Ссылка из
  цепи называет обе половины — [`<pinref inst gate pin>`](pinref.md).
