# `<attr>`

*пользовательский атрибут*

> 🟡 **Изменение формата, решено 2026-07-31, в коде не сделано.**
> Обёртка `<attributes>` упразднена — `<attr>` лежит прямым ребёнком носителя
> везде. См. [CHANGES.md](CHANGES.md).

| | |
|---|---|
| **Встречается в** | компонент, устройство, экземпляр компонента, **цепь**, схема, плата |
| **Родители** | [`<component>`](component.md), [`<device>`](device.md), [`<compinst>`](component-instance.md), [`<net>`](net.md), [`<schematic>`](schematic.md), [`<layout>`](layout.md) |
| **Дети** | — |

**Обёртки нет.** `<attr>` — прямой ребёнок носителя. Раньше в
[`<component>`](component.md) и [`<device>`](device.md) он лежал внутри
`<attributes>`, а в экземпляре и на плате — прямо; разнобой достался от Eagle,
где обёртка есть только на уровне документа.

Обёртка не несла ничего: своих атрибутов у неё нет, тег `<attr>` и так уникален,
а различить пользовательские данные от структурных фактов позволяет само имя тега
(см. [«атрибут — всегда `<attr>`»](naming.md)). Зато она давала **два способа сказать «атрибутов нет»** —
элемента нет либо элемент пуст.

## Атрибуты

| Атрибут | Тип / единицы | Смысл |
|---|---|---|
| `name` | Строка | Ключ |
| `value` | Строка | Значение — литерал **или формула**, если начинается с `=`. Пустое — это объявление ключа, а не отсутствие — см. [«пустое значение — объявление»](naming.md) |
| `type` | `bom` / `sim` / `general` / `service` | **Предназначение атрибута.** По умолчанию `general` |

## Значение может быть формулой

Сырое значение, начинающееся с `=`, — [вычисляемое](placeholders.md):

```xml
<attr name="R2" value="=R1@VALUE * (VOUT.Vtarget / IC1@Vref - 1)" />
```

В отличие от формулы в [`<text>`](text.md), которая рендерится и исчезает,
формула здесь **определяет значение атрибута**: на него можно сослаться.

Три правила, которые это ограничивают:

- **Ссылаться на формулу нельзя.** Формула не может читать атрибут, чьё сырое
  значение само начинается с `=` — hard reject в точке разрешения ссылки. Цепочка
  всегда ровно один шаг, циклы исключены без обхода графа.
- **Эхо — исключение:** тело ровно из одной голой ссылки без операторов
  (`=VOUT.value`) не создаёт узла и читать формулу вправе.
- **Формула живёт на экземпляре**, не в библиотечном символе: тот не знает, какая
  цепь придёт на его пин.

Подробности и обоснование — [Плейсхолдеры](placeholders.md).

## `type` — ось предназначения

Атрибуты однородны как данные, но не однородны по назначению. `type` говорит,
**для чего** ключ заведён:

| Значение | Для чего | Примеры |
|---|---|---|
| `bom` | Закупка и производство | `MANF#`, `LCSC#`, `DIGIKEY#` |
| `sim` | Моделирование | SPICE-параметры |
| `service` | Служебное | внутренние пометки инструментов |
| `general` | Всё прочее, значение по умолчанию | `TOLERANCE`, `POWER`, `VMAX` |

**Ради чего это нужно: маршрутизация.** BOM собирается из атрибутов с `type="bom"`,
и колонки в нём — объединение реально присутствующих bom-ключей. Без оси
предназначения BOM либо взрывался бы от SPICE-параметров и служебных пометок, либо
требовал бы отдельного списка «что считать закупочным» — второго места для того же
факта.

### Выводить `type` из имени ключа запрещено

`MANF#` → `bom` — **эвристика**, и потому недопустима. Имя ключа задаёт
пользователь, завтра он назовёт поле `ПАРТНОМЕР`, и правило рассыплется молча.

### Ни один КАД такого понятия не имеет

Отсюда жёсткие правила обращения:

| | |
|---|---|
| **Импорт** | Всё приходит с `type="general"` — взять неоткуда |
| **Экспорт** | `type` **игнорируется** — положить некуда |
| **Заполнение** | Только руками в редакторе |

Это ось **для будущего редактора**, а не для конвертации. В живых данных сейчас
`general` у всех 2890 атрибутов, и это правильное состояние, а не недоделка.

## Правила

- **Выделенных элементов под атрибут нет** — ни `value`, ни `description`, ни
  BOM-поля не имеют своей тумбочки — [«атрибут — всегда `<attr>`»](naming.md).
- **Пустое значение не отбрасывается** при импорте: это объявление схемы
  семейства — [«пустое значение — объявление»](naming.md).
- **`type` не выводится** ни из имени ключа, ни из значения.
- Разрешение значения: [«ближний побеждает»](naming.md) — экземпляр > устройство > компонент.
